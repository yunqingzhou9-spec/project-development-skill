# Proportional work and fast continuation

Use this guide only for ordinary work, planned idle handoff or native child routing. Existing Task checks and accepted project policy take precedence. Historical records and verdicts remain linked, not copied into current summaries.

## Ordinary work

For a new clear low-risk local task, the main Agent may implement and report targeted self-checks. High-risk work keeps distinct independent behavior verification and review; other selected or stricter project checks remain. A failure or consequential uncertainty expands the relevant investigation. Cache objective evidence only when inputs, command, environment/dependencies and scope match exactly; never cache ownership, native writer observations, approvals or candidate verdicts after deliverable changes.

## Idle window handoff

Use the same verified Project ID, repository identity, checkout and shared local registry. No helper can authenticate native IDs, prove writers stopped, fence shell writes or coordinate another host. Supply an actual native owner/worker observation reference; `native_writers: UNVERIFIED` from `inspect` is a reminder, not evidence. Preserve dirty files. The fingerprint includes raw bytes and modes of Git-visible dirty tracked and untracked files, plus index/worktree diffs. Ignored files and changes Git treats as clean lie outside this boundary. Read-only inspection rejects WAL-mode registries before opening SQLite; use explicit manual reconciliation for that non-default journal. Submodules or a mismatch require manual reconciliation.

Aim for an ordinary offline handoff or takeover within 10 seconds; more than one minute is a performance investigation signal, never an expiry, abort, forced claim or reason to omit checks. Permission, model and host scheduling can prevent that target. Continue safely while valid work is progressing; investigate only the actual obstruction. Existing per-command I/O limits still protect against a hung process; they do not make uncertain mutations safe to retry.

### Normal path

Read only project AGENTS, the current short state pointer and this handoff section. An idle handoff inside the authorized scope needs no new goal-confirmation round. Do not load completed Tasks, historical state, full coordination history, helper source or unrelated references unless a mismatch calls for them. Treat the old prompt as routing data, not current proof. Use its previous owner to query that native session directly; query relevant workers too. Prefer a compact native status/result over a full chat inventory or transcript. The current window's empty child tree alone does not prove the old window has no workers. If identities or stop evidence are missing, use bounded discovery rather than guessing.

1. **Outgoing:** stop dispatch, reconcile actual native owner/workers and unresolved attempts, and update the current state pointer only if its active scope, blockers or next action changed. Keep `next_action` about work after takeover (for idle work: wait for Human), not the mechanics of claiming. With fresh native evidence and known owner/generation, invoke `handoff.py prepare --project ... --repository ... --checkout ... --owner ... --generation ... --native-check-ref ... --state-path PROJECT_CURRENT.md --context '{"active_task":"NONE","next_action":"Wait for Human instructions","blockers":[]}' --record`. Choose the actual project-relative pointer; the default remains `PROJECT_STATE.md`. The helper checks ownership and outstanding attempts, fingerprints twice, saves the state index, releases and verifies the outcome. Pass its generated prompt only after `coordination.state: RELEASED` and `verification.status: VERIFIED`; then cease coordinating.
2. **Incoming:** read the instructions/pointer and obtain fresh native writer evidence, batching independent reads where possible. With the supplied binding and expected generation, invoke `handoff.py takeover --project ... --repository ... --checkout ... --owner ... --expected-generation ... --native-check-ref ... --record`. The helper checks RELEASED, unresolved attempts, the exact saved locator, HEAD, branch, dirty bytes/modes and state index before a conditional new-generation claim; it then rechecks files and ownership. Its verified result replaces a separate follow-up status/diff call. With `active_task: NONE`, wait for Human instructions; do not replay Tasks.
3. **Report immediately:** give the released/acquired generation, preservation result, next action and available elapsed measurement in a short reply. `--record` saves a private machine-generated receipt during that same call. Do not write a custom timing wrapper, manually reconstruct a large audit or update unchanged project files before replying.

A separate `handoff.py inspect` is useful when owner, generation or pointer routing is absent/uncertain; it is not a mandatory duplicate of checks already performed by `prepare`/`takeover`. Its compact output supplies coordination, local fingerprint, saved pointer and generation, without private context/history. `native_writers: UNVERIFIED` still requires a real native check. All three commands freshly read relevant local state: do not cache ownership, writer observations or dirty fingerprints to save time. The `coordinator.py status/assert` commands are read-only too; Python callers must use `Coordinator(..., read_only=True)`. Never read a registry through the default writable constructor just to inspect it.

The generated private prompt includes the resolved shared registry locator. Pass that same `--registry` value to incoming commands, including inspect when needed; do not silently fall back to a different default or create another ledger. Keep this locator and native owner references in private handoff/runtime material, never portable project files.

Use one appropriately scoped permission request for a known required local operation where the host supports it; do not deliberately repeat an already-known sandbox denial. Never change global permissions, bypass a denial or infer access from a previous window. If a mutation response is uncertain, reconcile current ownership before any retry. A postcheck failure reports `RECONCILE_REQUIRED` alongside the returned acquired/released generation; do not claim no mutation occurred or automatically release/retry it. Receipt failure is a separate warning and cannot undo ownership or justify another claim.

### Timing without extra orchestration

The helper returns `elapsed_ms` and named local phases under `timing`; the CLI adds `cli_elapsed_ms`. These are local intervals, not user-visible end-to-end latency. `--record` is only for prepare/takeover and writes outside the checkout under the private registry directory; inspect remains strictly read-only. Receipts contain helper timing/outcome and deliberately exclude the later receipt write, print, tool return and final response. Unknown end-to-end, permission-only, model-only and host-roundtrip values are null. Do not label wall time outside Python as pure permission wait or pure model time.

Use already available host request/turn timestamps for end-to-end measurement, and host tool-call timestamps for round trips. The full interval ends when the final response completes; it usually cannot be known while drafting that response. If only a first-tool-to-claim interval is available, label that partial interval explicitly. Save the available facts in the normal receipt, say which values are unavailable, and leave completed-turn auditing to a later requested diagnosis. Do not poll your own chat or add setup calls just to manufacture an exact total. Do not sum overlapping parallel calls, subtract hypothetical network delays or claim the 10-second target was met from a subsecond helper measurement.

These commands are local and have no network or reinstall step. If a snapshot is absent, a field differs, a native writer is uncertain or an attempt remains unresolved, stop the fast path and use [manual coordination](COORDINATION.md#stop-and-recover). Do not auto-reset, discard dirty work or claim solely because a lease aged. Resume with only the checks relevant to the mismatch; a full historical audit or full retest is not the default handoff cost.

A network hostname change is harmless after stable host binding. A legacy hostname-only registry needs the one-time [explicit migration](COORDINATION.md#stable-host-identity-and-explicit-legacy-migration); do not redo historical checks or alter the system hostname.

## Native child routing

Configure per-task tiers using models and effort levels the current native tool actually supports; a suggested default is `gpt-6-luna` low/medium for obvious bounded work, `gpt-6-luna` high for scoped tracing, `gpt-6-sol` medium for ordinary implementation, and `gpt-6-astra` low/high for complex or high-risk reasoning. Risk also determines independent checks; model choice never substitutes for independence. Pass a short assignment with Task, scope digest, base/candidate and needed files. Use a minimal context fork when the native tool supports it and an explicit model override requires it. A full-history fork that cannot override the model should use its actual inherited model; do not pretend routing happened.

Choose the model when creating a child, not in flight. If a chosen model is unavailable, select another supported model that preserves the task's required capability and assurance; otherwise block the selected check and report it. On capability failure, make one bounded escalation with a changed reason or evidence, not repeated blind attempts. An uncertain creation response requires native reconciliation before any retry. Do not change global configuration or call an external model API for routing.

Measure elapsed command time, host round-trip/wait time, calls and attempts separately when available. Report token, cost or remaining usage only from an actual host meter; label unavailable measurements `UNAVAILABLE`. Never turn reduced steps into a fabricated quota saving.
