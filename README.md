# Project Development｜许愿机（测试版）

> **先陪你把目标和需求想清楚，再把它一步步做出来。**

## 它能帮你做什么

你可以在一个对话窗口里，从一个想法开始，逐步做出可以运行的软件。

想法还模糊时，许愿机会先和你一起弄清楚：想解决什么问题、第一版做什么、哪些可以先不做，以及怎样才算完成。等你确认“这就是我想做的”，再开始制作。

接下来，它会拆分任务，按需要安排子智能体开发、检查和修改，做好后交给你体验和确认。简单的改动直接处理，复杂的工作再分工。

**你不必懂编程，也不必自己管理一群 AI。你负责一起想清楚目标、做关键决定；许愿机负责把事情往前推进。**

## 安装

在 Codex 或 ChatGPT Work 中，发送同一段提示词：

> 请从 https://github.com/yunqingzhou9-spec/project-development-skill 安装最新版 Project Development（Skill 名称：project-development）。先检查当前环境是否支持安装和使用；支持时，按仓库安装说明安装远程可获取的最新版本并验证，完成后告诉我版本和如何开始使用；不支持时，说明原因和可行的安装方式。

## 从一个想法开始

不需要先写好完整需求，直接说：

> 用 $project-development 帮我做一个管理客户的小工具。我还没想清楚具体功能，先陪我确定目标和第一版要做什么。

你们会这样一起推进：

```text
你：说出想法
→ 你和许愿机：一起想清楚目标、需求和取舍
→ 你：确认第一版做什么、怎样才算完成
→ 许愿机：拆分任务，按需要安排子智能体制作
→ 许愿机：组织检查、修复问题并再次验证
→ 你：体验结果，确认完成或提出改进意见
```

如果需求已经明确，也可以直接交代要做什么，不必重新走一遍讨论。只想聊想法时，加一句“先讨论，暂时不要改”。

## 提需求和看进度

继续在同一个窗口说你想要的结果：

> 增加按客户姓名搜索的功能，保留现有客户信息。

> 现在完成了什么？还有什么问题？下一步准备做什么？

> 继续上次没做完的部分。

许愿机会读取项目记录，继续推进；遇到影响结果的重要选择，再请你决定。

## 换窗口继续

按“旧窗口交接 → 新窗口接管”的顺序操作，不用复制整段聊天。

**1. 在旧窗口说：**

> 准备交接：保存进度，妥善结束正在运行的工作并停止协调，确认可以交接后，给我一句带项目位置的接管提示词。

等旧窗口明确回复“可以交接”，再进行下一步。如果还有工作未结束，它会说明需要等待或处理什么。

**2. 在新窗口粘贴它给出的接管提示词，例如：**

> 用 $project-development 接管项目，目录是 `<项目目录>`。先核实交接状态，确认没有其他窗口仍在修改，再继续未完成的工作。

旧窗口应把实际项目目录填好；新窗口会从项目文件读取编号、需求和进度。接管后，继续在新窗口提需求，不要让旧窗口同时修改同一项目。

如果旧窗口已经关闭，也可以直接使用接管提示词。新窗口会先检查能否安全恢复；无法确认旧窗口或子智能体已停止时，会请你处理，不会强行接管。换电脑或运行环境时，先确保新窗口能访问最新项目文件，再提供对应位置。

## 使用前了解这些

- 它需要能读取和修改项目文件的环境；多人分工还需要所在环境支持子智能体。
- 检查能帮助发现问题，但不能保证没有遗漏；遇到无法继续的问题，会说明原因和需要你决定的事项。
- 同一项目同时只由一个窗口协调；不同电脑之间不会自动同步进度或阻止冲突。
- 做好后由你体验和确认。公开发布、部署等操作，需要得到相应授权。

当前版本为 **2.2.0**；本地源码、远程可安装版本和实际安装版本可能不同。

需要了解技术细节时，可查看[安装说明](references/INSTALL.md)、[工作记录格式](references/WORK_FORMAT.md)和[本地协作说明](references/COORDINATION.md)。
